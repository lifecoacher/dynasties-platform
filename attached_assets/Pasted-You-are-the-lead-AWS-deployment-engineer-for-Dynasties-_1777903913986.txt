## PHASE 1 — REMOVE REPLIT URL COUPLING

### Problem
Production Stripe and return URLs are still built from:
- REPLIT_DOMAINS
- REPLIT_DEV_DOMAIN

On AWS these are undefined, producing URLs like:
- https://undefined/api/stripe/webhook
- https://undefined/settings/billing?checkout=success

### Required fix
Add a required `PUBLIC_BASE_URL` env var.

Implement:
- add `PUBLIC_BASE_URL` to the Zod env schema
- require it in production and staging
- validate it is a valid HTTPS URL outside local dev
- replace every use of `REPLIT_DOMAINS` / `REPLIT_DEV_DOMAIN` used for public URLs in:
  - artifacts/api-server/src/index.ts
  - artifacts/api-server/src/routes/stripe-billing.ts
  - artifacts/api-server/src/routes/stripe-connect.ts
  - any other file constructing Stripe webhook, checkout, portal, return, onboarding, or OAuth callback URLs

Rules:
- local/dev may use localhost fallback only if explicitly local
- AWS/staging/prod must use `PUBLIC_BASE_URL`
- never create public URLs from Replit env vars in AWS mode

Validation:
- Stripe webhook URL uses `${PUBLIC_BASE_URL}/api/stripe/webhook`
- Stripe checkout success/cancel URLs use `${PUBLIC_BASE_URL}/settings/billing?...`
- Stripe Connect onboarding refresh/return URLs use `PUBLIC_BASE_URL`
