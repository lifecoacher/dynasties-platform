# PHASE 1 — INGEST IDEMPOTENCY (CRITICAL UX FIX)

## Problem
Clicking "Ingest" multiple times duplicates intelligence entries (e.g., same port risk appears twice).

## Requirements
- Ingest must be **idempotent**
- Re-running ingest should NOT create duplicate records

## Implementation options (choose best based on current schema):
- Deduplicate at DB level:
  - use unique constraints (e.g., on sourceId + signalId or equivalent)
  - or upsert instead of insert
- OR deduplicate at service layer:
  - check existing records before insert
- OR mark ingestion runs and prevent reprocessing identical data

## UI behavior:
- If ingest is already complete:
  - show message: “Intelligence already up to date”
- Optional:
  - convert button to “Re-ingest” with confirmation

## Output requirement:
- confirm deduplication strategy used
- confirm duplicates no longer appear after repeated ingest
