## FIX 1 — Real DB Role Separation (NOT theoretical)

Problem:
API currently runs using DATABASE_URL (migration-level privileges). APP_DATABASE_URL is supported in code but not provisioned in infra.

Required:

1. Create a proper least-privilege Postgres role:
   - name: app_user
   - permissions:
     - SELECT, INSERT, UPDATE, DELETE on application tables
     - NO schema migration privileges
     - NO role management privileges

2. Ensure role creation is idempotent:
   - Use SQL like:
     DO $$ BEGIN
       CREATE ROLE app_user LOGIN PASSWORD '...';
     EXCEPTION WHEN duplicate_object THEN NULL;
     END $$;

3. Grant privileges safely:
   - GRANT usage on schema
   - GRANT DML on tables
   - ALTER DEFAULT PRIVILEGES for future tables

4. Create APP_DATABASE_URL:
   - Add new SSM parameter
   - Format: postgres://app_user:password@host/db

5. Terraform:
   - Inject APP_DATABASE_URL into ECS API task ONLY
   - Keep DATABASE_URL for migration task ONLY

6. Runtime behavior:
   - API must prefer APP_DATABASE_URL
   - Migration runner must use DATABASE_URL

Validation:
- API container uses app_user
- Migration task uses admin/migration user
- App runs correctly with reduced privileges
- No silent GRANT failures
