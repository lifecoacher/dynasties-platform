- claims SHA-256 deduplication

- only prevents duplicates on subsequent runs in same session
- displays duplicates directly in the UI (Control Tower)

## GOAL

- running ingest any number of times produces identical data state
- no duplicate intelligence entries appear in UI
- existing duplicates are cleaned

- existing records are NOT matching the dedup check

Common failure patterns to check:
- timestamps included in hash
- non-deterministic fields in hash
- different schemas between ingest and read layer
- multiple tables (raw vs processed vs aggregated)
- hashing before normalization
