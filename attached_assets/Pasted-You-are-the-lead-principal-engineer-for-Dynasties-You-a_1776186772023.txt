PHASE 1 — PILOT-BLOCKING FIXES (MUST COMPLETE)
==================================================

1. Stripe credential decoupling from Replit
Current problem:
- stripeClient.ts fetches credentials via Replit Connectors API only
- this breaks outside Replit and blocks AWS
Required fix:
- refactor stripeClient.ts so it first checks:
  - STRIPE_SECRET_KEY
  - STRIPE_PUBLISHABLE_KEY if needed
  - STRIPE_WEBHOOK_SECRET where relevant
- only fall back to Replit connector credential retrieval if direct env vars are absent and Replit connector env is actually present
- make the fallback explicit and safe
- add clear structured logging of which credential source is being used
- do not log secrets
Validation:
- test mode still works in current environment
- non-Replit env path is now viable

2. DB-backed Stripe webhook idempotency
Current problem:
- webhook dedup uses in-memory Set
- restarts cause duplicate processing risk
Required fix:
- add a dedicated table for processed Stripe webhook events
  suggested fields:
  - id
  - stripeEventId (unique)
  - type
  - receivedAt
  - processedAt
  - status
  - metadata/error
- before processing a webhook, atomically insert or no-op on stripeEventId
- if event already exists and is processed, skip safely
- if event exists but failed, define safe retry behavior
- preserve correct signature verification flow
- do not rely on process memory for payment correctness

3. Remove or hard-gate dev role override
Current problem:
- x-dev-role-override header can escalate role when NODE_ENV !== production
Required fix:
- remove it entirely from non-local paths, OR
- gate it behind FEATURE_DEV_ROLE_OVERRIDE=true and LOCAL_DEV_ONLY=true
- ensure it is impossible for this path to be active unless both:
  - explicit feature flag is true
  - environment is a recognized local/dev environment
- default must be disabled
- add tests for this
- if disabled and header is sent, ignore it and log at debug level only

4. Add Helmet middleware
Current problem:
- no security headers
Required fix:
- install/configure helmet in API server
- add sane defaults for:
  - X-Frame-Options
  - X-Content-Type-Options
  - Referrer-Policy
  - HSTS where appropriate outside local dev
- configure CSP thoughtfully if needed, but do not break the app
- verify Stripe/webhook/body parsing flows are unaffected

5. Wrap accounting sync in DB transactions
Current problem:
- syncCustomer() and syncInvoice() perform multi-step operations without transaction safety
Required fix:
- wrap all multi-step accounting sync paths in db.transaction()
- ensure lookup/update/mapping insert/connection update/event emit persistence are consistent
- if external QB API succeeds but internal DB write fails, persist a recoverable error state instead of partial silent corruption
- document chosen compensation strategy where true rollback over external side effects is impossible
- add tests for partial failure handling
