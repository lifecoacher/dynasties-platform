## PHASE 1 — CRITICAL FIXES

### 1. Fix migration drift
Problem:
- Two migrations share the 0003 prefix:
  - 0003_recommendation_hardening.sql
  - 0003_romantic_lester.sql
- Drizzle journal only references 0003_romantic_lester.
- 0003_recommendation_hardening.sql will never run.

Required fix:
- Resolve properly using Drizzle migration tooling.
- Do NOT hand-edit the journal unless absolutely unavoidable.
- Preferred:
  - delete/rename the orphaned migration
  - regenerate as next clean migration, e.g. 0005_recommendation_hardening.sql
  - ensure meta journal/snapshot includes it
- Verify on scratch DB that migration applies.
- Confirm columns/indexes added:
  - recommendation fingerprint column
  - superseded_by_id column
  - recommendations_active_fingerprint_idx or equivalent unique/partial index

### 2. Make CI actually run tests
Problem:
- CI runs `pnpm test --if-present`
- no package has a test script
- test suite is effectively a no-op.

Required fix:
- add root `test` script
- install/configure Vitest
- create `vitest.config.ts`
- ensure real tests run in CI
- for API/E2E tests that need a live server:
  - gate with env flag such as `E2E=true`
  - skip clearly when env is absent
- CI must show real test count, not zero.

### 3. Fix process-level error handlers
Problem:
- `uncaughtException` and `unhandledRejection` currently log and continue.
- This is unsafe.

Required fix:
- keep handlers, but change behavior:
  - log full error and stack
  - start graceful shutdown
  - stop accepting new requests
  - close HTTP server if accessible
  - close DB pool if accessible
  - set timeout 10–30 seconds
  - call `process.exit(1)`
- Do not keep process alive after uncaught exception.
- Let ECS/container supervisor restart.

## PHASE 2 — MAJOR PRODUCTION HARDENING

### 4. Enable strict Helmet CSP
Problem:
- Helmet exists but `contentSecurityPolicy: false`
- COEP also disabled.

Required fix:
- enable strict API-safe CSP.
- Recommended baseline:
  - `default-src 'none'`
  - `frame-ancestors 'none'`
  - allow only what API genuinely needs
- Make sure Stripe webhooks, Clerk webhooks, QuickBooks OAuth callback, health endpoints still work.
- Keep frontend CSP separate if needed.

### 5. Tighten CORS
Problem:
- non-production allows all origins with credentials.
- if NODE_ENV is wrong, production can become permissive.

Required fix:
- require explicit allow-list.
- never use `origin: true` with `credentials: true`.
- allow localhost only through explicit dev defaults or env.
- fail closed in production if allowed origins are missing.
- validate env in Zod schema.

### 6. Remove default JWT secret
Problem:
- docker-compose has public fallback secret while NODE_ENV=production.

Required fix:
- remove fallback:
  - no `${JWT_SECRET:-dev...}` in production-like compose
- update Zod env validation to reject known bad substrings:
  - `dev`
  - `change`
  - `example`
  - `secret`
  - `password`
  where appropriate
- app must fail boot if JWT_SECRET is weak or missing outside explicit local demo mode.

### 7. Pin pnpm version consistently
Problem:
- Dockerfiles use pnpm@9
- root packageManager uses pnpm@10.26.1
- CI likely uses 10.x

Required fix:
- update all Dockerfiles to:
  - `corepack prepare pnpm@10.26.1 --activate`
- pin GitHub Actions pnpm setup to the same version.
- root package.json remains source of truth.

### 8. Replace console-based logging with Pino
Problem:
- Pino exists but API request path uses console.*
- 164 console calls remain in API server.

Required fix:
- import/use registered Pino logger from lib/config.
- replace request logger with Pino.
- add request ID / correlation ID.
- attach request-scoped child logger to request context if practical.
- log:
  - method
  - path
  - status
  - duration
  - requestId
  - userId if available
  - companyId if available
- configure redaction for:
  - Authorization header
  - cookies
  - emails
  - Stripe IDs/secrets where appropriate
- replace core API `console.*` calls where practical.
- Leave only unavoidable boot-time console if necessary.
